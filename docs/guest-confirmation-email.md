# ゲスト予約の確認メール

Resendで予約受付メールを自動送信します。キャンセル待ちは参加確定と区別します。

## 本番設定

1. Resendアカウントを作成し、所有ドメインを登録して指定のDNSレコードを設定・認証します。
2. Resendの送信用APIキーを作成します。
3. Vercelの環境変数に以下を設定します（秘密値をGitに入れないでください）。
   - `RESEND_API_KEY`：Resend APIキー
   - `GUEST_CONFIRMATION_FROM`：認証したドメインの送信元（例 `イベント受付 <events@example.com>`）
   - `SUPABASE_SERVICE_ROLE_KEY`：Supabaseのサーバー専用service roleキー。NEXT_PUBLIC接頭辞を付けないでください。
   - `NEXT_PUBLIC_SITE_URL`：本番サイトのURL
   - 既存の `NEXT_PUBLIC_SUPABASE_URL` も使用します。
4. Supabaseに `supabase/migrations/20261025090000_guest_confirmation_email.sql` を適用します。
5. Vercelを再デプロイし、自分のメールアドレスでゲスト予約して受信を確認します。

設定が不足している場合は、新しいゲスト予約を受け付ける前にエラーを表示します。設定とSQL適用を揃えてから公開してください。ログイン会員の申込み処理は変更していません。

## 送信失敗と再試行

予約と送信記録は同じDBトランザクションで作成します。送信失敗時も予約は有効です。画面に受付番号と再試行ボタンを表示します。同じ画面からの再試行では同じ受付IDとResendの冪等キーを使います。ページ再読み込み後には新規申込みを繰り返さず、主催者へお問い合わせください。

自動バックグラウンド再送はありません。24時間の冪等キー有効期間を超える重複送信を避けるため、23時間を超えた再試行は送信しません。送信記録は `guest_confirmation_emails` に保存され、一般ユーザーからは参照できません。`sent` は配信サービスが受理した状態であり、受信箱への到達保証ではありません。

予約時点の内容をメールに記載します。以後の日程変更・キャンセル待ち繰上げ通知はこの処理の対象外です。

## ローカル検証

`node --test tests/guest-confirmation.cjs` はメール・DBをモックして実行します。実メールは送りません。
